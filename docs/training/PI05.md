# π0.5/RH56 training


## 首次取得源码、容器和权重

此流程与遥操作安装分离，本轮部署不启动训练。DH 电爪不能直接复用 RH56 的 12 维训练接口。

1. 执行 `git submodule update --init --recursive third_party/openpi`，保持
   [`openpi.lock.json`](../../configs/training/pi05/openpi.lock.json) 固定的源码版本，不单独升级子模块。
2. 准备锁文件指定的 `jaka-openpi:thor-cuda13` 容器。当前仓库没有该本地镜像的 Dockerfile 或公共 registry；
   新用户需向维护者取得可审查的镜像归档/构建来源，而不是把任意镜像改成同名。
   `training/pi05/scripts/check_openpi.sh --require-image` 只检查已配置源码与镜像可用性，不证明新镜像与旧环境完全等价。
3. 按[数据集文档](../data/DATASET.md)取得授权的原始 episode，并建立当前任务所需的 master/view。
   历史实验数据和微调 checkpoint 不在 Git，也不应从其他用户的私有目录隐式读取。
4. 提前准备官方 JAX `pi05_base` 权重：上游给出的来源是
   `gs://openpi-assets/checkpoints/pi05_base`；本项目 weight loader 使用其中的 `params`。
   参见[锁定版本的 OpenPI 官方 README](https://github.com/Physical-Intelligence/openpi/blob/15a9616a00943ada6c20a0f158e3adb39df2ccac/README.md#model-checkpoints)。

官方 OpenPI 使用 `openpi.shared.download.maybe_download` 下载并缓存权重，`OPENPI_DATA_HOME` 可指定缓存根目录。
在已经安装锁定 OpenPI 依赖、允许联网的**训练环境**中可执行：

```python
from openpi.shared import download
print(download.maybe_download("gs://openpi-assets/checkpoints/pi05_base"))
```

设置 `OPENPI_DATA_HOME` 到自己的缓存目录后再运行上述代码。项目 supervisor 的默认主机缓存是
`outputs/training/pi05_rh56/openpi_cache`（可用 `PI05_OPENPI_CACHE` 修改），运行时挂载到容器的
`/root/.cache/openpi`。supervisor 使用 `--network none`，缺少权重时不能靠启动训练自动联网下载。
保留下载器生成的缓存结构；权重、JAX cache 和训练产物均不提交到 Git。

For a new user, the pinned source is obtainable through the submodule, but the local Thor container, authorized lab data and trained checkpoints are separate prerequisites.
The official `pi05_base` source and downloader are documented above. Pre-populate the configured cache in a network-enabled training environment before using the network-disabled supervisor.
The RH56 action interface does not establish DH compatibility.

## English

This is the project-specific OpenPI adapter for the fixed task prompt
`Pick up the bottle and place it on the cardboard box.` It initializes
`pi05_base` with the official JAX LoRA path. The native state/action boundary is
12-D: six JAKA arm values plus six active RH56 channels; OpenPI's internal projection is handled
by the adapter without inventing independent RH56 joints. Source force is
preserved but not used by this first baseline.

The current config and runtime are:

- `configs/training/pi05/physical_bottle.yaml`;
- `configs/training/pi05/openpi.lock.json`;
- `training/pi05/openpi_adapter.py`;
- `training/pi05/scripts/openpi_runner.py`;
- `training/pi05/scripts/train_weekend.sh`.

Check the pinned runtime, then use the training-only supervisor:

```bash
training/pi05/scripts/check_openpi.sh --require-image
training/pi05/scripts/train_weekend.sh start
training/pi05/scripts/status.sh
training/pi05/scripts/train_weekend.sh resume
```

The supervisor uses local logs/checkpoints and resume without overwrite. It
does not connect to JAKA, RH56, Quest, or cameras.
